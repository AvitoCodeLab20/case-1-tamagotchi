# Питомец, действия и прогрессия

## Жизненный цикл питомца

1. После регистрации пользователю создаётся один питомец со стартовыми
   характеристиками.
2. Клиент получает состояние питомца и доступные типы активности.
3. Пользователь выполняет действие, передавая его `activity_code`.
4. Сервер проверяет действие и в одной транзакции обновляет состояние питомца,
   опыт, уровень, стрик и ежедневную сводку.

У одного пользователя может быть только один питомец. Это обеспечивается
ограничением `UNIQUE` для `pets.user_id`.

## Состояние питомца

Состояние хранится в таблице `pets` и включает следующие характеристики:

| Поле | Диапазон | Значение |
| --- | ---: | --- |
| `health` | `0..100` | Здоровье питомца |
| `hunger` | `0..100` | Текущий показатель сытости |
| `happiness` | `0..100` | Настроение питомца |
| `energy` | `0..100` | Запас энергии |

В текущем MVP большее значение каждой характеристики означает лучшее
состояние питомца. Поэтому `hunger = 100` фактически означает, что питомец сыт.
Название поля сохранено таким же, как в БД; после MVP его стоит переименовать
в `satiety`, чтобы убрать смысловую неоднозначность.

Все характеристики ограничиваются диапазоном `0..100`: действие не может
увеличить значение выше 100 или уменьшить ниже 0. `state_version` увеличивается
при каждом изменении состояния и позволяет не перезаписать новое состояние
устаревшими данными.

## Типы активности

Типы активности хранятся в серверном справочнике `activity_types`. Клиент
получает только активные записи с `is_active = true`.

| Поле | Назначение |
| --- | --- |
| `code` | Стабильный код действия, передаваемый в API |
| `title` | Название для интерфейса |
| `description` | Объяснение действия пользователю |
| `category` | Категория `care` или `avito_product` |
| `base_experience` | Базовый опыт за успешное выполнение |
| `daily_limit` | Максимальное число начислений за день или `null` без лимита |
| `cooldown_seconds` | Минимальная пауза между одинаковыми действиями |

Категория `care` предназначена для непосредственного ухода за питомцем.
Категория `avito_product` связывает прогрессию с подтверждёнными действиями в
основном продукте Авито, например с публикацией объявления или оформлением
доставки.

Клиент не передаёт `experience_awarded` и `state_delta`. Эти значения вычисляет
сервер по типу активности и текущему состоянию питомца. Событие категории
`avito_product` должно подтверждаться доверенным серверным источником; одного
запроса от клиента недостаточно для начисления опыта.

## Выполнение действия

Для каждого успешного действия создаётся запись в `pet_actions`:

- `activity_code` указывает выполненный тип активности;
- `experience_awarded` фиксирует фактически начисленный опыт;
- `state_delta` хранит фактическое изменение характеристик;
- `occurred_at` фиксирует время выполнения действия;
- `idempotency_key` защищает от повторного начисления.

Проверка действия и все связанные изменения выполняются в одной транзакции:

1. Блокируется строка питомца пользователя.
2. Проверяются `is_active`, `daily_limit` и `cooldown_seconds`.
3. Создаётся запись `pet_actions`.
4. Обновляются характеристики, `experience`, `level`, `state_version` и
   `last_interaction_at` питомца.
5. Обновляются `user_streaks` и `daily_summaries`.

Если дневной лимит исчерпан или кулдаун ещё не завершился, сервер возвращает
`409 Conflict` и не изменяет данные.

## Прогрессия и уровни

- Общий опыт питомца хранится в `pets.experience` и никогда не уменьшается.
- Порог каждого уровня задаётся в `levels.required_total_experience`.
- Текущий уровень — максимальный уровень, порог которого не превышает
  накопленный опыт.
- Одно действие может повысить питомца сразу на несколько уровней.
- Название текущего уровня берётся из `levels.title`.

При повышении уровня модуль питомца передаёт подтверждённое событие модулю
наград. Сам модуль питомца не создаёт и не применяет награду.

## Непрерывный стрик

Стрик считается по календарным дням московского времени.

- Первое успешное действие пользователя начинает стрик длиной 1 день.
- Первое действие на следующий календарный день увеличивает `current_days`
  на 1.
- Несколько действий в один день не увеличивают длину стрика повторно.
- Если между активными днями есть пропуск, новый стрик начинается с 1 дня.
- `longest_days` хранит максимальную длину стрика пользователя и не уменьшается.
- `last_active_date` хранит последний календарный день с успешным действием.

При достижении установленной длины стрика модуль питомца передаёт
подтверждённое событие модулю наград.

## Ежедневная сводка

Сводка формируется отдельно для каждого календарного дня московского времени.
Она содержит:

| Поле | Назначение |
| --- | --- |
| `summary_date` | День, за который сформирована сводка |
| `action_count` | Число успешных действий за день |
| `experience_earned` | Суммарный опыт, начисленный за день |
| `levels_gained` | Число полученных за день уровней |
| `state_before` | Состояние питомца перед первым действием дня |
| `state_after` | Состояние питомца после последнего действия дня |
| `generated_at` | Время последнего пересчёта сводки |

Для пары `user_id + summary_date` существует не более одной сводки. При каждом
успешном действии запись создаётся или обновляется. Если в указанный день
успешных действий не было, API возвращает `404 Not Found`.

## Безопасность

- `user_id` берётся только из проверенного access-токена. Клиент не передаёт
  владельца питомца или действия ни в теле, ни в параметрах запроса.
- Сервер проверяет, что питомец принадлежит аутентифицированному пользователю.
- `activity_code` проверяется по серверному справочнику `activity_types`.
- Опыт, изменение характеристик, новый уровень и стрик вычисляет только сервер.
- `POST /api/v1/pet/actions` требует `Idempotency-Key` в формате UUID. Повтор
  запроса с тем же ключом возвращает ранее полученный результат и не начисляет
  опыт второй раз.
- Один `Idempotency-Key` нельзя повторно использовать с другим содержимым:
  сервер возвращает ошибку `idempotency_conflict`.
- Дневной лимит и кулдаун проверяются в той же транзакции, в которой создаётся
  действие, чтобы параллельные запросы не обходили ограничения.
- Действия категории `avito_product` начисляются только после подтверждения
  доверенным серверным источником.

## Граница с другими модулями

Модуль питомца использует следующие входы и формирует следующие выходы:

| Направление | Событие или данные | Обязательные данные | Владелец |
| --- | --- | --- | --- |
| Вход | Пользователь зарегистрирован | `user_id`, имя питомца | Авторизация |
| Вход | Пользователь аутентифицирован | `user_id` в request context | Авторизация |
| Вход | Подтверждено действие в Авито | `user_id`, `activity_code`, время, внешний идентификатор | Интеграция с Авито |
| Выход | Достигнут новый уровень | `user_id`, `level`, время | Прогрессия → награды |
| Выход | Достигнута длина стрика | `user_id`, `current_days`, `last_active_date`, время | Прогрессия → награды |
| Выход | Начислен опыт | запись `pet_actions` с `user_id`, XP и временем | Питомец → лидерборд |

Лидерборд, выдача и применение наград, а также регистрация и работа с токенами
не входят в модуль питомца.

## API

Предлагаемый контракт находится в [`openapi.pet.yaml`](openapi.pet.yaml).

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/v1/pet` | Получить питомца, текущий уровень и стрик пользователя |
| `GET` | `/api/v1/activity-types` | Получить активные типы действий |
| `POST` | `/api/v1/pet/actions` | Выполнить действие и получить обновлённое состояние питомца |
| `GET` | `/api/v1/progress` | Получить уровень, общий опыт и текущий стрик |
| `GET` | `/api/v1/daily-summaries/current` | Получить сводку за сегодняшний день |
| `GET` | `/api/v1/daily-summaries/{summary_date}` | Получить сводку за указанную дату |
